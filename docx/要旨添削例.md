# 要旨添削例.md — 正解ラベル付きの添削例（few-shot）

`要旨AGENTS.md` の決まりを、実際の原稿でどう当てはめるかを示す例集である。
決まりだけでは「どの文のどこがダメか」を見つけにくいので、実際に添削で指摘された文と、その直し方を並べる。

- **要旨を書く前**と、**自己添削のとき**（`要旨AGENTS.md` §14.2）に読む。
- 添削を頼まれたら、§3 の形式で指摘を返す。
- 例は研究室の添削コメント付き要旨（2026 年度、36 本）から取った。原稿の書き手と添削者の名前、研究室の機体名は伏せ、
  引用された論文の著者名は X ら・Y ら に置き換えた。研究の中身の語は、例を理解するのに要る範囲で残した。
- 元の PDF は `要旨学習/` の中（git の管理外。フォルダ名は `CLAUDE.local.md`）にある。
- このファイルは GitHub に上げる。個人名・組織名（大学、研究室、指導教員）を書かない。例を足すときも伏せる。

**例の読み方**

- **原文** のうち、ダメな箇所を〘 〙で囲む。
- **種類** は §1 の記号。1つの文に複数の種類があれば並べる。
- **直した文** の出典を次のように示す。
  - 〔次の版〕：書き手が次の回の原稿で直した文（添削を受けて本人が直したもの）
  - 〔添削者〕：添削コメントに書かれていた直し方
  - 〔作成〕：指摘を元に、`要旨AGENTS.md` の決まりに合わせて作った案（数値などは例であり、事実ではない）
- 〔次の版〕の文にも直しきれていない点が残る場合は「なお」で書き添えた。

---

## 1. 種類（ラベル）

| 記号 | 種類 | 見分け方（読み手の心の声） |
|---|---|---|
| A | 構成・課題 | 結局、課題は何？ 目的はどれ？ それ、前に書いてあった？ |
| B | 説明不足 | 何の〇〇？ 〇〇とは？ |
| C | 理由がない | なぜそれを使う？ なぜその値？ なぜその比較？ |
| D | 曖昧・数値がない | 具体的には？ 何回？ 何 cm？ |
| E | 文の形 | 長い。主語はどれ？ どこで切れる？ |
| F | 用語 | さっきと呼び方が違う。この略語は何？ |
| G | 語の選び方 | 話し言葉。言い過ぎ。強すぎる。記号の使い方が違う |
| H | 図・表・式 | 図と本文が合わない。この記号は何？ |
| I | 引用・文献 | 出典は？ どの文献がどの主張の根拠？ |
| J | 冗長・不要 | それ、要る？ さっきも読んだ |
| K | 実験 | 再現できない。判定が主観。結果と考察が混ざる |
| L | 表題・見出し | 何の章？ 表題と中身が違う |

## 2. 例

### A 構成・課題

**A-1 目的と手段が入れ替わっている**（はじめに）

- 原文：本研究の目的は，2軸ジンバル機構を開発し，〘姿勢補正の有無による自己位置推定誤差の変化を評価すること〙である．
- 種類：A、B
- ダメな点：評価は目的を確かめる手段であり、目的ではない。目的は、背景で述べた課題（傾斜路で自己位置推定の精度が落ちる）を
  解決することである。また「2軸ジンバル機構」「姿勢補正」がこの文で初めて出ており、何の機構・何の補正かが分からない。
- 直した文〔次の版〕：本研究の目的は，傾斜路走行時の走査面を水平に近づけ，自己位置推定の精度低下を抑えることである．

**A-2 誰の研究にも当てはまる背景から書き始めている**（はじめに、最初の文）

- 原文：〘近年，我が国では少子高齢化の進行に伴う生産年齢人口の減少により，医療・介護施設や飲食店をはじめとするサービス業における人手不足が深刻な社会問題となっている．〙
- 種類：A、G
- ダメな点：液体を運ぶ移動ロボットの研究だが、この文はどのロボットの研究にも書ける。読み手に何の情報も与えない
  （`guide.tex` の背景の節と同じ指摘）。「近年」も使わない。
- 直した文〔作成〕：移動ロボットが液体の入った容器を載せて走行すると，加減速と旋回によって容器内の液面が揺れ，液体がこぼれる．

**A-3 課題を並べすぎて、どれを解くのか分からない**（はじめに）

- 原文：しかし，この方式は〘多数のロールアウトと人手観察を要するためスケーラビリティに乏しく，二値評価ではどのサブタスクで失敗したかを定量化できず，強化学習の報酬信号としても粗い〙という課題がある．
- 種類：A、B、E
- ダメな点：課題を3つ1文に並べており、本研究がどれを解くのかが分からない（添削：ここまでで、課題が結局なに？）。
  ロールアウト、サブタスクも定義していない。
- 直した文〔作成〕：しかし，成否の二値評価では，1回の試行のどの段階で失敗したかを定量化できない．
  （本研究で扱わない2つの課題は削る）

**A-4 本文で述べていない課題を、おわりにで初めて出している**（おわりに）

- 原文：また，〘多人数クラスにおける個別指導の限界〙を補うため，「AIエージェントとHuman-in-the-Loopを活用した教育者支援システム」の構築を目指す．
- 種類：A、G
- ダメな点：本文のどこにも課題として書かれていない内容が、おわりにで初めて出る。本文で「」も使っている。
- 直し方〔作成〕：おわりにから削る。扱うなら、はじめにで課題として述べ、実験で確かめる。

**A-5 接続詞が前の文と論理的につながっていない**（はじめに）

- 原文：〘一方で〙OECD PISA 2022によると，挑戦や失敗を前向きな学びの資源と捉えるグロース・マインドセットの低下が指摘されており，初学者に「成功実感」と「適時の診断的フィードバック」を提供する学習環境の構築が〘不可欠〙とされている[2]．
- 種類：A、G
- ダメな点：前の文と対立しない内容を「一方で」でつないでいる。前の文の主張を強める根拠なので、何に対する「一方で」かが分からない。
  「不可欠」は強すぎる語で、「」も使っている。
- 直した文〔作成〕：OECD の PISA 2022 は，失敗を学びの機会と捉える学習者が減っていることを報告しており，初学者に成功の実感と
  適時の助言を与える学習環境が必要とされている[2]．

**A-6 引用した文献が述べていないことを根拠にしている**（はじめに）

- 原文：特に実機を用いたロボットプログラミング教育は，センサの誤認識や照明変動，物理摩擦といった不確実性を伴う実空間の〘課題解決力を養う上で重要である[1]〙．
- 種類：A、I
- ダメな点：添削者が文献[1]を確かめたところ、[1]は実機とシミュレータで教育効果に差が無いことを述べていた。
  原典が述べていない主張の根拠に使っている。
- 直し方〔作成〕：原典を読み直し、原典が述べている範囲に主張を合わせるか、主張を支える別の文献を探す。

**A-7 課題の原因が書かれておらず、読み手が逆の意味に取れる**（はじめに）

- 原文：〘障害物過多の環境〙において人がロボットの追従を意識することなく移動方向を自由に変化させた場合，ロボットがそれに適応して旋回と障害物回避を行い，〘人への追従を安定して維持することが困難である〙．
- 種類：A、D
- ダメな点：なぜ追従できなくなるのかが書かれていない。この書き方だと「ロボットが適応して旋回と回避をする」と読め、
  むしろ追従できているように読める。「障害物過多」も、障害物がいくつ、どう置かれた環境なのかが分からない。
- 直した文〔添削者〕：しかし，従来の手法では人とロボットの間に障害物が存在する場合，経路生成に失敗して追従できない場合がある．

### B 説明不足

**B-1 「何の」が書かれていない**（手法）

- 原文：MPPIは，確率的なサンプリングにより生成された多数の未来軌道に対し，予測ホライズン内の総コストを評価し，〘最適な制御入力〙を導出する手法である．
- 種類：B
- ダメな点：制御入力が何か（速度か、角速度か）が書かれていない。
- 直した文〔次の版〕：MPPIは，確率的なサンプリングにより生成された多数の未来軌道に対し，予測ホライズン内の総コストを評価し，最適な速度と角速度を導出する手法である．

**B-2 自分で作った語を定義せずに使っている**（手法）

- 原文：d0はばねの自然長であり，〘追従の理想距離〙を表す．
- 種類：B、F
- ダメな点：「追従の理想距離」が何か、誰がどう決めるのかが書かれていない。
- 直した文〔次の版〕：d0はばねの自然長であり，目標距離を表す．
  なお、目標距離を誰がどう決めるか（実験での値）も書く。

**B-3 初めて出る語に説明がない**（はじめに）

- 原文：最後に，検索した〘ノード〙の画像から対象物体の位置を推定し，ナビゲーション位置を算出する．
- 種類：B
- ダメな点：「ノード」がここで初めて出るが、何をノードとしているのかが分からない。
- 直した文〔作成〕：地図の作成時には，画像を撮影した地点をノードとして地図に登録する．場所の検索では，指示に最も近いノードの画像から対象物体の位置を推定し，ナビゲーション位置を算出する．

**B-4 何に対する値かが分からない**（関連研究）

- 原文：Xら[3]は〘シミュレータの真値〙を用いた障害物回避を提案しているが，センサによる深度推定の実装には至っていない．
- 種類：B
- ダメな点：何の真値か（障害物の位置か、深度か）が分からない。
- 直した文〔作成〕：Xら[3]は，シミュレータが出力する障害物の正確な位置を用いた障害物回避を提案しているが，センサで障害物の距離を推定する処理は含んでいない．

**B-5 見出しの語が何を指すか分からない**（実験の章題）

- 原文：4．〘一致率〙を用いた階層認識実験
- 種類：B、L
- ダメな点：何と何の一致率かが分からない。
- 直した文〔次の版〕：4．BSSIDの一致率を用いた階層認識実験

### C 理由がない

**C-1 選んだ項目の理由がない**（手法）

- 原文：本研究では，表1に示す〘Task，Object，Location，Destinationの4種類〙をスロットとして定義する．
- 種類：C
- ダメな点：命令の情報はほかにもある（数量、色）のに、なぜこの4種類なのかが書かれていない（発表でも質問された）。
- 直した文〔作成・書き手の返信を元に〕：本研究は物品を運ぶ命令を対象とし，命令の理解に最低限必要な Task，Object，Location，Destination の4種類をスロットとする（表1）．
  数量と色は，確認質問による補完の基本的な処理を確かめるため，本研究では扱わない．

**C-2 比較する理由がない**（実験）

- 原文：〘さらに，確認質問を行わず，初回のLLM出力のみを使用する方法と比較する．〙
- 種類：C、G
- ダメな点：何を確かめるための比較なのかが書かれていない。「使用する」は「用いる」にする。
- 直した文〔作成〕：確認質問の効果を確かめるため，確認質問を行わず初回の LLM の出力だけを用いる方法と比較する．

**C-3 設定値の理由がない**（手法）

- 原文：VLMエピソードスコアリング指標では，〘1秒間隔〙でサンプリングしたVLMのYes/No系列から，…を算出する．
- 種類：C
- ダメな点：なぜ1秒間隔なのかが書かれていない。間隔は結果を左右するので必ず聞かれる。
- 直し方〔作成〕：対象物体が映る時間の長さと、1回の推論にかかる時間から、間隔を決めた理由を1文で書く。

**C-4 手法を選んだ理由がない**（手法）

- 原文：対象物体を〘HSV色空間の閾値処理〙で検出し，直前フレームでの検出位置に最も近い領域のみを追跡することで，類似色の別物体との混同を避ける．
- 種類：C
- ダメな点：学習済みの物体検出器ではなく、色の閾値処理を選んだ理由が書かれていない。
- 直し方〔作成〕：正解値を作るための処理であり、学習済みの検出器の誤りを正解値に含めないため、のように、選んだ理由を1文で足す（理由は事実に合わせる）。

**C-5 機種名を出す理由がない**（手法）

- 原文：移動中は〘Intel RealSense〙からRGB画像および〘PointCloud〙を取得し，RGB画像に対して〘YOLO〙を適用することで人物を検出する．
- 種類：C、F、I
- ダメな点：その機種でなければならない理由が無いのに機種名を出している。機種名を出すなら引用も要る。
  PointCloud は日本語の本文なら点群と書く。YOLO にも引用が無い。
- 直した文〔添削者の案を元に作成〕：移動中は RGB-D カメラから RGB 画像と点群を取得し，RGB 画像に物体検出器 YOLO[4] を適用して人物を検出する．
  （カメラの機種と型番は実験の章で書く）

### D 曖昧・数値がない

**D-1 「一定」を数値にしていない**（実験）

- 原文：対象物体の把持成功率は，対象物体を把持して〘一定高さ以上〙持ち上げることに成功した割合として評価する．
- 種類：D
- 直した文〔作成〕：対象物体を把持して作業台から 5 cm 以上持ち上げた試行の割合を，把持成功率とする．

**D-2 「複数回」を数値にしていない**（実験）

- 原文：各条件において，同一経路を〘複数回〙走行し，実験結果の再現性を確認する．
- 種類：D
- 直した文〔作成〕：各条件で同じ経路を 10 回走行する．

**D-3 「ほぼ」で結果を書いている**（実験結果）

- 原文：Accestについて，TableやChairは〘ほぼ全環境〙で正しく推定された．
- 種類：D、K
- ダメな点：何環境のうちいくつで正しかったのかを書く。
- 直した文〔作成〕：Table と Chair の家具名は，4 環境のうち 4 環境で正しく推定された．

**D-4 「十分な」を定義していない**（はじめに）

- 原文：ロボットがVLAモデルのデモから学習するには，各エピソードに指示対象物が〘十分な時間〙映っているフレーム〘（本研究ではこれを利用可能フレーム，十分な数含むエピソードを利用可能エピソードと呼ぶ）〙が必要である．
- 種類：D、G、B
- ダメな点：「十分な時間」「十分な数」が何秒・何枚か分からない。定義を丸括弧に押し込んでいる。
  そもそも、なぜ映っている時間が必要なのか（根拠）も書かれていない。
- 直した文〔作成〕：VLA モデルの学習に用いる動画では，指示された対象物が映っている必要がある[1]．本研究では，対象物が
  1 エピソードの 50 % 以上のフレームに映っているエピソードを，学習に利用できるエピソードと呼ぶ．

**D-5 評価の中身を書かずに「どう変化するか」で済ませている**（おわりに）

- 原文：本研究では，傾斜路走行時における2D LiDARの走査面の傾きが，…機構により，〘自己位置推定の精度がどのように変化するかを評価する〙．
- 種類：D、K、A
- ダメな点：最後まで、何を尺度に精度を測るのかが書かれていない（添削：必ず質問される）。評価を目的として書いている（A-1 と同じ）。
- 直し方〔作成〕：実験の章で評価尺度を定義する（例：到着地点での自己位置の推定値と実測位置の距離）。おわりにでは、その尺度での結果を書く。

### E 文の形

**E-1 「〜し，」でつないで長くなっている**（手法）

- 原文：そこで本研究では，骨格推定により推定した骨格キーポイントを用いて人物を部位ごとに〘切り出し，〙その人物特徴抽出にOSNet[2]を用いた対象者識別手法を開発する．
- 種類：E
- 直した文〔作成〕：そこで本研究では，骨格推定で得た関節の位置を用いて，人物の画像を部位ごとに切り出す．切り出した各部位の特徴は OSNet[2] で抽出する．

**E-2 1文に情報を詰め込みすぎている**（関連研究。PDF で6行の1文）

- 原文：Wi-Fi FPを用いた関連研究として，Xら[2]が屋内測位技術として，縦軸をWi-Fi AP固有識別番号のBSSID(Basic Service Set Identifier)，横軸を時間としたRSSIの数値の変化を画像として畳み込みニューラルネットワークを用いて学習させ，シミュレーション上で94%の精度で階層認識する研究が行われている．
- 種類：E、J
- ダメな点：1文が6行ある。関連研究として必要なのは「何をして、何が残っているか」で、入力の画像の作り方は要らない。
- 直した文〔作成〕：Xら[2]は，Wi-Fi の受信信号強度の時系列を畳み込みニューラルネットワークで学習し，シミュレーションで 94 % の精度で階を認識した．しかし，建物の各地点で事前に信号を計測する必要がある．

**E-3 「の」が続いている**（手法）

- 原文：〘提案手法の処理の流れを図1に示す．〙
- 種類：E
- 直した文〔添削者〕：図1に提案手法の流れを示す．

**E-4 助詞の順で読みにくい**（手法）

- 原文：〘家具名を撮影地点が所属する部屋の領域に対応させることで〙家具が従属する部屋領域を決定する．
- 種類：E
- ダメな点：「家具名を」の後に「撮影地点が」が割り込み、何を何に対応させるのかが読みにくい（添削：書いたら声に出して読む）。
- 直した文〔添削者〕：撮影地点が所属する部屋領域と家具名を対応させることで，家具が従属する部屋領域を決定する．

**E-5 主語が途中で入れ替わる**（実験結果）

- ダメな点：正解率の「正解」を何にするか（誰がどう作った正解か）が書かれていない。尺度が4つあり、どれが主要尺度かも分からない。
- 直し方〔作成〕：正解のスロットを誰がどう作ったかを書き、主要尺度を1つ決めて理由を書く（`guide.tex` 実験方法の節）。

**K-6 おわりにで数値だけを書いている**（おわりに）

- 原文：評価対象とした家具に対し，平均で1.000の家具検出率と〘0.856の部屋従属の正解率を達成した〙．
- 種類：K
- ダメな点：0.856 が高いのか低いのか分からない。比べる相手との結論を書く。
- 直し方〔添削者〕：比べる相手（従来手法・条件）に対してどうだったかを書く。満点（1.000）になった理由も考察で述べる。

**K-7 計算機の仕様が GPU だけ**（実験方法）

- 原文：推論は〘NVIDIA GeForce GTX1060 with Max-Q Design（VRAM 6GB）上で〙，…実行する．
- 種類：K
- 直し方〔添削者〕：CPU、メモリ、GPU、OS をまとめて表にする（`guide.tex` の表1の例）。

### L 表題・見出し

## 3. 良い書き方の例

直す例だけでなく、良い書き方も真似る。過去の修士論文の要旨から取った（著者名は X ら・Y ら に置き換えた）。

**P-1 関連研究と「会話」している**

> Xら[2]は，ヒューマノイドロボットを用いて，トレイの上に物体を配置し，そのバランスを保たせることに成功した．…しかし，ロボットが移動の際に働く慣性に対応できるか検証されていない．それに対して，Yら[3]は，モバイルマニピュレータを走行させながら，複数の物体を運搬することができる．

- 良い点：研究ごとに、何をしたか → 残っている問題 を書き、次の研究と本研究につないでいる（`guide.tex` の関連研究の節の書き方）。

**P-2 課題の場面と原因を段を踏んで書いている**

> 従来研究[1]では，…服装の色合いや形状といった特徴を取得して対象者を識別する手法[2]を組み込んだ人追従走行ロボットシステムを開発した．…しかし，対象者と服装の色合いや形状が似た人物に遮られた際に，その非対象者を対象者と誤って識別し誤追従する場合があった．〘この手法〙では，低レベルな特徴マップに基づく粗い特徴量を用いて対象者分類を行っている．〘このため〙，服装の色合いや形状が似た人物は，対象者と類似した特徴量を示し，誤識別が発生しやすくなる．

- 良い点：どの場面で（似た服装の人に遮られたとき）、何が起き（誤追従）、なぜ起きるか（粗い特徴量）を段を踏んで書いている。
- 今の決まりで直す点：〘この手法〙〘このため〙は指示語なので、「従来研究[1]の識別手法は」「その結果，」と書く。

**P-3 結果を、比べる相手と絶対値で書いている**

> 実験結果より，従来手法の識別成功割合が 65 % に対して，本手法が 95 % を示し，対象者識別精度の向上を確認した．

- 良い点：相対的な差だけでなく、両方の絶対値を書いている（`guide.tex` の実験結果の節）。表でも何回中何回かを示している（20 回中 19 回）。

## 4. 添削を頼まれたときの出力形式

原稿を添削するときは、§2 の例と同じ形で、文ごとに返す。1つの文に複数の問題があれば種類を並べる。

```
[B 説明不足・E 文の形] 2.2節 第1段落
- 箇所：「最適な制御入力を導出する」
- ダメな点：制御入力が何か（速度か、角速度か）が書かれていない。
- 直した文：…最適な速度と角速度を導出する手法である．
```

- 並べる順は、原稿の頭からの順とする。最後に、多かった種類と、原稿全体で直すべきこと（課題が定まっているか、目的と実験が対応しているか）を3行以内でまとめる。
- 事実が要る直し（数値、理由、文献）は、作らずに「書き手に確認」と書く。
