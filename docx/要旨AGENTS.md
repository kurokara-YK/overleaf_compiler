# 要旨AGENTS.md — 要旨の書き方

研究室発表・学会の**要旨（予稿）を書く・直すエージェント向けの決まり**。
同じ階層の `AGENTS.md` は overleaf-compiler（道具）の要件であり、このファイルとは別物である。
道具の使い方は `AGENTS.md` と `README.md` に従い、**原稿の中身の書き方はこのファイルに従う**。

ここに書いてあることは、本文を1文でも書き換える前に必ず守ること。

**基準は `要旨学習/学会原稿テンプレート/`（指導教員が作ったもの）である。** `template.tex` が雛形、
`guide.tex` が書き方の指南（各章で何を書くか、表題の付け方、図表、文量）。要旨を書く前に `guide.tex` を必ず読み、
このファイルと食い違うときは `guide.tex` に従う。`要旨学習/` は git の管理外（他人の原稿を含むため）なので、
無ければ使う人に置き場所を聞く。

**このファイルと `要旨添削例.md` は GitHub に上げる。個人名・組織名（大学、研究室、指導教員）・個人の URL を書かない。**
原稿の置き場、研究メモの場所、資料のフォルダ名のように使う人に結びつく情報は、同じ階層の `CLAUDE.local.md`
（git の管理外）に書き、要旨を書く前に読む。無ければ使う人に聞く。
このファイルは、`guide.tex` の要点と、添削で受けた指摘（学会予稿の添削 2026-09-17〜18、
研究室発表の要旨への指摘 2026-09-28）をまとめたものである。
さらに、研究室の要旨の添削コメント（2026 年度の要旨 36 本、コメント 1362 件、添削者 約 25 人。2026-09-28 集計）と、
所属研究室と近い分野の研究室の卒業論文と修士論文の要旨（2020〜2025 年度）、一般的な技術文書の書き方（§15）から決まりを足した。
情報源の優先順は **`guide.tex`・`template.tex` ＞ 添削コメント ＞ 一般的な書き方 ＞ 過去の要旨** とする
（添削は学生どうしのものが多く、指導教員の指南と食い違えば指南に従う）。過去の要旨は章立てと分量の見本であり、
文体は真似しない（古い要旨ほど「など」「この」「〜と考えられる」が多く、今の添削で指摘される書き方を含む）。
添削で繰り返し受ける指摘の順位と、書いた後の見直しの問いは §14 にまとめた。
**実際に指摘された文と直し方（正解ラベル付きの例）は、同じ階層の `要旨添削例.md` にある。** 決まりだけでは
どの文のどこがダメかを見つけにくいので、書く前と自己添削の前に必ず読む。

## 1. ファイルの構成（1つのファイルに全部を書かない）

テンプレートと同じく、部品ごとにファイルを分ける。新しい回はテンプレートから部品を複製して作る。

```
data/<ワークスペース>/<回>/      置き場は CLAUDE.local.md を見る
├── main.tex          プリアンブル・表題・著者・\input だけ。本文は書かない
├── chapter/
│   ├── 01_introduction.tex   はじめに（図1のポンチ絵もここ）
│   ├── 02_related.tex        関連研究
│   ├── 03_<提案>.tex         提案手法・システム
│   ├── 04_<実験>.tex         実験（実験が2つなら 04・05 に分ける）
│   └── 0N_conclusion.tex     おわりに
├── reference.bib     文献（BibTeX）。先頭のコメントに各文献の確認方法を書く
├── img/              写真・画像の図
├── rsj2025j.sty      テンプレートから複製（書き換えない）
├── ipsjunsrt.bst     テンプレートから複製（書き換えない）
└── latexmkrc         テンプレートから複製（pLaTeX）
```

- `main.tex` はテンプレートどおり `\documentclass[dvipdfmx,twocolumn]{jarticle}` と `\usepackage{rsj2025j}`。
  パッケージは `main.tex` にだけ書き、章ファイルには `\usepackage` を書かない。
- 文献は `\bibliographystyle{ipsjunsrt}` と `\bibliography{reference}`。本文は `\cite{キー}` で引用し、
  `thebibliography` を手で書かない。
- 図は、それを最初に引用する章ファイルに置く。TikZ で描く図もその章ファイルに書く。
- 前回の原稿フォルダは上書きしない。原稿フォルダに `.md`（CLAUDE.md を含む）を置かない（Overleaf 用 zip に入る）。

## 2. 研究室発表の要旨の書式

| 項目 | 決まり |
|---|---|
| 分量 | **A4 で 2 ページちょうど**。3 ページ目に1行でもはみ出したら削る。1 ページ半で終わるのも不可 |
| 表題 | `\title{}`。§3 の決まりに従う |
| 著者 | 研究室内の発表は `\author{学籍番号 名前（指導教員 〇〇）}`。学会発表は `\author{名前 先生の名前（大学名）}`。研究室内の要旨で添削を受けたら、添削者の**名字だけ**を指導教員と同じ行に書く（改行しない）。添削を受ける前には書かない |
| 英文要旨 | **研究室発表の要旨には書かない**（`\abstract{}` を消す。不要と指示された 2026-09-28）。学会の規定で求められたときだけ、英語で1段落3〜6行（100語程度）で書く |
| 行間 | テンプレートの `\setlength{\baselineskip}{4.4mm}` のまま変えない |

## 3. 表題と章題

**表題**（`template.tex` の注記どおり）

- 論文の究極の要約である。研究の特徴（何を、どうやって）が入るようにする。
- **1行に収める。** 副題は入れない。
- 「〇〇の研究」「〇〇の検討」「〇〇の提案」で終えない（検討・提案しただけと読まれる）。評価まで含む表現がよい。
- 研究の焦点が変わったら表題も変える。前回の表題を惰性で使わない。
- 研究が最終的に何を実現するのか（何のための研究か）が伝わるようにする。今回の作業（実装・環境構築）だけを表す表題にしない。
- 表題に入れた語（比較・設計・評価 等）は本文で回収する。本文に出てこない語を表題に入れず、本文の範囲を表題より広げない。

**章題**

| 章 | 章題 |
|---|---|
| 1 | **はじめに** |
| 2 | **関連研究**（先行研究ではない） |
| 3 | **提案手法・システムの中身を表す題**（例：外見を引き継ぐマルチロボット配膳システム）。「提案手法」「システム」だけの題にしない |
| 4 | **何の実験かが分かる題**（例：着席客からの注文者識別実験）。「実験」「評価実験」だけの見出しは不可 |
| 最後 | **おわりに**（「まとめ」「まとめと今後の予定」にしない） |

実験の章の節は `guide.tex` の順に **実験目的／実験方法・環境／実験結果／考察・限界**。
節の題も内容に合わせて変えてよい（例：比較手法と評価尺度）。
章・節・小節は木構造にする（上位の見出しは下位の内容をすべて含む。話題の区切りで切らない）。
節の題も何の節かが分かるようにする（「概要」「実装内容」「機構の構成」だけにせず、何の概要・何の機構かを書く）。
**節は2段落以上で書く。** 1段落しかない節は作らず、前後の節にまとめる。

**実験の前の要旨（進捗報告）**：章題を「〇〇実験の計画」とし、節は実験目的／実験方法・環境／比較手法と評価尺度にする。
**未測定の数値・結果は書かない。** 予想は「〜と予想する」と書き、実験目的の節に置く。

## 4. 各章に書くこと

### 4.1 はじめに（短くしない。1段の大半を使ってよい）

段落ごとに1つの主張を置き、段落の先頭文で主張を述べる（パラグラフ・ライティング）。次の順で書く。

1. **最初の一文で、この研究独自の主題・課題を述べる。** 「近年，〜が求められている」「人手不足により〜」の
   ような、誰の研究にも当てはまる広い背景から書き始めない。
2. 課題が実在することの根拠（実店舗・製品・統計・自分の予備実験）を出典付きで示す。
   抽象的な言葉には具体例を添え、造語には定義を添える。
3. 現状の方法（対抗手段）の限界を事実で示す。論破しようとしない。
4. 本研究の考え方と、そのときの技術的な課題。
5. **研究の全体像の図（ポンチ絵）を図1として置き、段落の頭で「研究の全体像を図1に示す．」と引用する。**
6. 目的・リサーチクエスチョン（問いの形で書く）・貢献。

背景は提案と実験の伏線である。背景で書いた課題は、必ず実験で確かめる（伏線の回収）。論理の飛躍（AだからC）に注意する。

添削で繰り返し受けた指摘（§14 で最も多い種類の1つ。はじめにへの指摘が一番多い）：

- **課題は1つに絞る。** 読み終えた人が「この研究の課題は何か」を1文で言えるようにする。
  課題を3つも4つも並べると「結局課題は何か」と聞かれる。
- **誰の研究にも当てはまる背景（人手不足、「近年〜が注目されている」）は書かない。** 書くなら3行以内にし、
  研究独自の場面（その課題が起きる現場）に紙面を使う。「近年」「最近」は使わない。
- **目的と手段を入れ替えない。**「〜を評価する」「〜を比較する」を研究の目的にしない。評価は、目的を達成できたかを
  確かめる手段である。
- **課題は根拠と共に言い切る。**「〜しにくくなる可能性がある」で止めると、問題であることが伝わらない。
  何が、どの場面で、どう困るのかを書く。
- **後出しをしない。** はじめにで述べていない課題・用語・比較の必要性を、手法や実験の章で初めて出さない。
  表題に「比較」とあるなら、比較が必要な理由をはじめにで述べる。
- **説明の順序は、課題 → 既存の方法で解けない理由 → 本研究の考え方** とする。研究の歴史を年代順に語らない。
- **研究室の前のシステム（従来研究）があれば、それを起点に書く**（過去の修士論文の要旨の型）。
  1段落目で研究の場面と困りごと、2段落目で従来研究が何をどうしているか → どの場面で何が起きるか → なぜ起きるか、
  3段落目で「そこで本研究では」とつなぐ。従来研究の文献を引用する。
- **日常語で呼ばれる仕組み（番号札、呼び出しベル、整理券 等）は、何を指すかを本文で定義してから使う。**
  同じ語でも店によって使い方が違う（例：客が卓上に置いて店員が席まで届けるための札と、客が鳴ったら取りに行くベル）。
  定義しないまま限界を論じると、別の使い方では成り立たない主張になる。
- 読み手は、同じ分野だが自分の研究を知らない研究者とする。初めて読む人が1回で分かる書き方にする。

### 4.2 関連研究（3〜6件、他の研究機関の論文）

関連研究と「会話」をする。研究ごとに **何をしたか → 本研究との関係 → 残っている問題** を書く。

- 良い例：研究AはXを行っているが，Yを扱っていない．本研究はXとYを同時に行うことでZを明らかにする．
- 悪い例：研究AはXをやっていない．研究BはYをやっていない．（欠点を並べるだけ）
- 否定しない、闘わない。紹介は簡潔にする。
- 章の最後に全体をまとめる一文（「以上のように〜は扱われていない」）を置かない。関係は研究ごとに書く。
- 関連研究は、本研究の立ち位置（何が既にでき、何が残っているか）を示すために書く。相手の研究のデータの規模や
  処理の細部は書かない（知りたい人は文献を読む）。1〜2文で、本研究と比べたい点だけを書く。
- 1件だけでは少ない。対象が同じ研究が無ければ、課題が近い研究や手法が近い研究を挙げる。
- **引用する研究が何を述べているかは原典で確かめる。** 原典が述べていないこと（例：「実機を使う教育は課題解決力を養う」）を
  根拠にしない。反論する相手の研究の前提（何を対象にしているか）を取り違えない。

### 4.3 提案手法・システム

- 処理の流れの図を置き、段落の頭で引用する。説明は図を主にし、文章で補う。
- 機体の固有名詞は使わず、役割名（注文ロボット・配膳ロボット等）で書く。機体との対応は1度だけ述べる。
- 前提（範囲）は1文で明記する。
- 既存手法の一般的な解説は、後の議論に必要な最低限に留める（2枚物では特に）。
  使った道具の内部の仕様（シミュレータが内部で行う変換 等）は、本研究の手法ではないので書かない。
- 各処理は **目的（〜のために）→ 処理 → 得られるもの** の順に書き、入力と出力をはっきりさせる。
- **選んだ理由を書く。** 手法・モデル・センサ・機構・閾値・間隔を選んだ理由を、ほかの選択肢と比べて1文で書く
  （「なぜその検出器か」「なぜ検出器が要るのか」「なぜ1秒間隔か」は必ず聞かれる）。
- **本文は役割名で書き、製品名・型番は実験の章で書く**（例：本文は RGB-D カメラ・移動ロボット、実験の章で機種と型番）。
  型番は再現のために要る（センサ・通信機器の規格が分からないと再現できない）。
- **式の書き方：** 式の前に、その式で何を求めるかを1文で述べる。式は言及した直後に置き、「式(1)により〜を算出する」と
  番号で引く（「次式」「以下の通り」としない）。式中の記号はすべて式の直後で定義する。ベクトルと行列は太字にする。
  記号の定義と式を離して書かない。

### 4.4 実験

- 研究の目的と実験の目的は違う。実験目的は具体的で検証可能に書く（何を明らかにするか、何と何を比べるか、どうなれば言えるか）。
- 第三者が再現できるように、環境・人数・条件・試行回数を書く。
- 比較手法（ベースライン）と評価尺度は、**選んだ理由**と **主要尺度がどれか** を書く。
  閾値・条件の値・試行の設定（人数、物体の配置、区間）も、そう決めた理由を書く。
- **条件は数値で書く。**「複数回」「一定距離」「十分な時間」「高密度」「大幅に」「ほぼ」を使わず、回数・距離・秒・割合で書く。
  確定した値に「約」「およそ」を付けない。
- **評価尺度は定義を書く**（何を何で割るか。式で示せるものは式で示す）。成功・失敗の判定方法も書く。
  **目視や著者の主観で判定しない。** やむを得ない場合は判定の基準を書く。
- 実験環境は図で示す（縮尺、出発点と目標、障害物の位置）。実環境とシミュレーションで同じ環境かどうかも書く。
- 使用機器（ロボット、センサの型番、計算機）は実験の節にまとめる。計算機は GPU だけでなく CPU とメモリも書く。表にしてよい。
- **結果の節には結果だけを書く。** 条件や前提を結果の節で後から足さない。結果を先に述べ、考察はその後に分けて書く。
- 結果は表か図で示し、本文には表の読み方と要点を書く。比べる相手（従来手法・条件）が無い数値は、良いのか悪いのか判断できない。
- 満点や 0 のような極端な結果には、なぜそうなったかの考察を書く（必ず質問される）。

### 4.5 おわりに

- 背景・目的から実験までを要約する。新しいことは書かない。表題を回収する。
- **今後の予定は書かない**（研究室発表の要旨でも不要と指示された 2026-09-28）。`guide.tex` は研究グループ内の発表で
  予定を書くならガントチャートで示すとしているが、書くよう求められたときだけにする。
- 本文で述べていない課題・用語を、おわりにで初めて出さない。はじめにと同じ語を使う（言い換えない）。
- 結果は数値だけでなく、比較の結論（従来手法と比べてどうだったか）で書く。
- 今後の課題は、実験で分かった本手法の限界に対応させる。今回の要旨で扱っていない大きな構想を並べない。
- 「〜する予定である」は、おわりにの今後の課題以外に書かない。

## 5. 冗長にしない

- **同じ内容を章をまたいで繰り返さない。** はじめにで述べた課題をシステムの章や実験の章で言い直さない。
  表や図に書いたことを本文で繰り返さない。
- 1つの段落で同じ主張を言い換えて重ねない。
- 補足の文を足さない。理由も含めて1文で書く。
- キャプションは図の読み方（記号・線の意味）に絞る。本文の繰り返しを書かない。
- 紙面は背景の一般論より、本研究の手法と実験に使う。はじめにと関連研究で紙面を使い切り、手法の説明が
  足りなくなった要旨が多い。

## 6. 文体

- **常体（である調）の書き言葉**で書く。口語は使わない。句読点は **，と．**。
- **1文は PDF の段組で3行以内、句点まで約70字以内。** 超えたら2文に分けるか修飾を削る。
  「〜であり，〜し，〜ため，〜」のように読点で3つ以上つなげない。
- 事実を淡々と述べ、言い切れることは言い切る。「〜と考えられる」を多用しない。
- **「など」を使わない**（何が含まれるか読み手に分からない）。列挙するなら全部書く。
- **指示語を使わない。**「これ」「これら」「この〜」「このような」「こうした」で前の内容を受けない。
  `guide.tex` のとおり「そして」も使わない。接続詞は、無くても文意が通るなら書かない。
- **主語を書く。** 誰が（ロボットが、利用者が、本手法が）行うのかが分からない文にしない。
- **「〜し，〜し，」「〜したうえで，」で文をつながず、「〜する．」で切る。**
  例：「特徴を抽出し，登録画像と比較し，同一人物かを判定する」→「特徴を抽出する．次に，登録画像と比較して同一人物かを判定する．」
- **「の」を3つ以上、「を」を2つ以上続けない。** 例：「提案手法の処理の流れを図1に示す」→「図1に本手法の流れを示す」。
- **用語は定義してから使い、定義を最後まで変えない。** 初めて出る専門用語・自分で名付けた語には、その場で意味を書く。
  「何の〇〇か」（何の動作・何に対する距離・何の真値）が分かるように修飾する。
- **同じものは同じ語で書く**（表記ゆれは添削で最も多い指摘の1つ。例：実機／実機ロボット、ドア／扉、
  2D LiDAR／LiDAR、シミュレーション環境／シミュレータ環境）。似た語の使い分けも決めて混ぜない
  （有効性／有用性、検出／認識、目的／目標）。並べる順（手法A・B・Cを述べる順）も全体でそろえる。
- **略語は初出で正式名称と併記する**（例：慣性計測装置（Inertial Measurement Unit：IMU））。「以下，〜と記す」の文を別に立てない。
- **言い過ぎない。**「全く」「完全に」「どのような姿勢でも」のように確かめていない範囲まで言わない。「〜すべきである」を書かない。
  ただし課題や結果は、確かめた範囲では言い切る。
- 丸括弧で補足を挟まない（「（本研究では〜）」）。必要なら本文の1文にする。
- 本文に変数名・ファイル名・コードの書き方（`target_class=lemon`、アンダースコア、`way.py`）を書かない。
- 句読点は全角の「，」「．」にそろえる（半角の「,」「.」を混ぜない）。並列に中黒「・」を使わず「AとB」「A，B，C」と書く。
- 数字は算用数字にそろえる（「第一」と「1つ目」を混ぜない）。範囲の書き方も1つにそろえる。
  「3つ目は」と書くなら1つ目と2つ目も同じ形で書く。
- 日本語の本文では「X ら」と書く。参考文献の「et al.」は斜体にする。
- **本文で「」を使わない。** ロボットの発話や用語の強調も地の文で書く。参考文献の題名に元から含まれる「」は残す。
- **（1）（2）の括弧書きの改行リストを使わない。** 条件も文章で書く。
- **造語・内部用語を使わない**（状態の名前 `SearchCustomer`、行動木、内部の段階番号など）。用語は全体で統一する。
- 使わない語と言い換え：

  | 使わない | 言い換え |
  |---|---|
  | そのまま置く、載置する | 配置する |
  | 聴取する | 尋ねる、音声認識により取得する |
  | 帰還する | 〜へ移動する |
  | 授受 | 受け渡し |
  | 手掛かり | 対応づける（動詞で書く） |
  | 古い順 | 先入れ先出し |
  | 組（客の） | グループ |
  | 動き回る、〜してもらう、すぐに移れる | 移動する、依頼する、再開する |
  | 使用する | 用いる |
  | 〜を行う（「検出を行う」等） | 〜する（検出する） |
  | 不可欠である | 必要である |
  | 本稿で報告する | 述べる |
  | 近年，最近 | 書かない（研究独自の課題から書き始める） |
  | 〜する予定である | 書かない（おわりにの今後の課題にだけ書く） |
  | 全く，完全に | 確かめた範囲に限って書く |
  | ほぼ，大幅に，十分な，一定の，複数回，高密度な | 数値で書く |
  | 〜すべきである | 書かない |
  | 〜の恐れがある | 〜の可能性がある（課題なら根拠と共に言い切る） |
  | 注目されている（既に広く使われている技術に） | 用いられている |
  | 主眼，三者，なお，あわせて，少なくない | 使わない（内容で言い換える） |
  | 撮像 | 撮影 |
  | 基礎技術 | 何の技術かを具体的に書く |

## 7. 引用

- **2ページの要旨の参考文献は6〜8件程度に絞る。** 14件は多すぎると指摘された（2026-09-28）。
  関連研究3〜6件＋背景の根拠1〜2件＋比較手法、が目安。
- **名前を出したソフトウェア・モデルには引用が要る。** 引用を増やさないため、後の議論に不要な道具の名前
  （検出器・通信ミドルウェア・顔認識モデル等）は本文に出さず、処理の内容で書く（例：ロボット間通信により送信する）。
- データセット・ロボット・競技の名前を出すときも引用が要る。
- 1つの主張に引用は1件。`[1, 2, 3, 4]` とまとめて付けず、各主張にそれぞれの文献を付ける。
- 本文の議論で使わない文献（引用として機能していない文献、内容が同じ2本目の文献）は載せない。
- 番号は本文に出る順に振られる（`ipsjunsrt` が自動で振る）。手で番号を書かない。
- arXiv の論文は、採録された会議・論文誌を確かめ、そちらを書誌にする。
- 書誌の書き方を全件でそろえる。3名以上の著者は `.bib` で `and others` と書くと「et al.」になる。
- **実在を確認した書誌だけを載せる。** 著者・題名・巻・ページは論文や出版社のページで確かめ、確かめられない項目
  （ページ等）は書かない。名は確かめられなければ頭文字にする。確認方法を `reference.bib` の先頭のコメントに書く。
  リンクが切れた記事は、同じ内容を報じた別の記事で確かめて差し替える。

## 8. 図表

- 図は段落の頭で「**〜を図Xに示す．**」の形で引用し、その後に読み方を書く。表も同じ。
- 図の中は短いラベルだけにし、述語のある文を書かない。図中の記号（R、S、T 等）を本文で使わない。
- 文字の大きさは本文程度にし、読めない小ささにしない。
- **表は右段の上、大きい表はページ幅（`table*`）でページの上部**に置く。1ページの上部に図表を詰め込まない。
  `[tb]` の図表は、置きたい段に組まれる段落の中に書く（左段で書くと左段の上に出る）。
- TikZ の線・文字と枠の重なりはエラーにならないので、必ず拡大した画像で確かめる。
- **要旨は図の説明で組み立てる**（`guide.tex`：理想は図の説明だけで研究の大筋の説明が終わること）。
  文章だけで長く説明している箇所があれば、先に図にできないかを考える（添削で最も多い指摘の1つ）。
- すべての図表を本文で引用する。引用の書き方は「図Xに示す」にそろえ、文末の「（図X）」と混ぜない。
- 処理の段階の数や用語を、図と本文で一致させる（本文で4段階なら図も4段階）。
- 色・記号・線には凡例を付ける。白黒で印刷しても区別できるようにする。
- 自分で作った図・自分の実験の画像を使う。他の研究の図や説明のない画像を貼らない。
- フローチャートの矢印は、どこからどこへ何が渡るのかを明確にする。条件分岐の「はい」「いいえ」は分岐の図形から出す。
- 複数の図を並べるときは (a)(b) を付け、`minipage` で並べて間を空ける。図は段の幅を超えない。
- 表では最も良い値を太字にし、何の値か（平均か、何回の試行か）を書く。

## 9. 作る手順

1. `要旨学習/学会原稿テンプレート/guide.tex` を読む。
2. 前回の要旨（直近の2回分）を読み、研究の到達点と前回からの変化をつかむ。
3. 研究メモを読む（場所は `CLAUDE.local.md`）。**日付の新しい節を正とする**。
4. §1 の構成で部品を複製し、表題・章題を決める（§3）。
5. 章ごとに書く（§4〜§8）。分量は2ページの1.5倍程度書いてから削る。
6. `overleaf-compiler check <原稿フォルダ>` で組版する（未定義の参照・文献が出たら、もう一度実行して解消を確かめる）。
7. PDF をページ画像にして目で確かめる（§10）。
8. 2 ページに収める（§11）。
9. §12 の確認をすべて行う。
10. §14.2 の問いで、初めて読む人の立場から自己添削する（書いた本人は文脈を知っているので気づかない）。

## 10. PDF の確かめ方

```bash
overleaf-compiler check <原稿フォルダ>
pdftoppm -r 80 -png <原稿フォルダ>/main.pdf <スクラッチ>/p        # 全ページを画像にして見る
pdftoppm -r 220 -f 1 -l 1 -x X -y Y -W W -H H -png main.pdf <スクラッチ>/fig   # 図だけ拡大して見る
pdftotext -f 3 -l 3 <原稿フォルダ>/main.pdf -                    # 3ページ目にはみ出した量を見る
```

画像はスクラッチ用のフォルダに書き出し、原稿フォルダには置かない。

## 11. 2 ページに収める

`guide.tex` のとおり、**構成を正すことと枝葉を削ぎ落とすことで削る。**
行間・図表の間隔・文字の大きさを詰めて押し込まない。はじめには削らない（短いと指摘された）。次の順で削る。

1. 章をまたいだ重複、図表と本文の重複を消す（§5）。
2. 補足の文を前の文へまとめる。
3. 後の議論に不要な道具の名前と、その引用を消す（§7）。
4. キャプションを図の読み方だけにする。

      （`・` `,` `.` は数式・URL・図の中の正しい使い方にも当たる。括弧は略語の併記や図の参照なら残してよい）
- [ ] 未測定の数値を書いていない

- [ ] 初出の略語に正式名称がある。表記ゆれがない（同じものを別の語で書いていない）
- [ ] 名前を出したソフトウェア・モデル・データセット・ロボットに引用がある

70字を超える文を探すスクリプト（原稿フォルダで実行）：

```bash
python3 - <<'EOF'
import re, glob
for f in sorted(glob.glob('chapter/*.tex')):
    s = open(f).read()
    s = re.sub(r'\\begin\{(figure|table)\*?\}.*?\\end\{\1\*?\}', '', s, flags=re.S)
    s = '\n'.join(l for l in s.splitlines() if not l.lstrip().startswith('%'))
    t = re.sub(r'\\cite\{[^}]*\}', '[1]', s)
    t = re.sub(r'\\ref\{[^}]*\}', '1', t)
    t = re.sub(r'\\(sub)*section\{[^}]*\}|\\label\{[^}]*\}', '', t)
    t = t.replace('\\,', '').replace('$', '').replace('\n', '')
    for x in t.split('．'):
        if len(x.strip()) > 70:
            print(f, len(x.strip()), x.strip())
EOF
```

## 13. 注文者再識別の研究の要旨で守ること

研究の内容に関する決まり。研究メモ（場所は `CLAUDE.local.md`）の方針が変わったら、ここも直す。

- **背景の軸はテーブルデリバリー**（カウンターで注文し、好きな席に着いた客の席まで届けるサービス）。
  「同じテーブルの誰に渡すか」は主軸にしない。
- **番号札は定義して使う。** 本研究で番号札と呼ぶのは、注文1件ごとに1枚渡し、客が卓上に置き、店員が番号を見て
  席まで届けるための札である。フードコートの呼び出しベル（鳴ったら客が受け取り口へ取りに行く）とは区別して書く。
  注文1件に1枚の札なら、客が自分の前に置けば誰の注文かも分かるので、「番号札は卓の位置しか示さない」とは書かない。
  番号札の限界として書くのは、配布と回収を担う店員が要ること（ロボットのみで運営する店舗にはいない）と、
  客が札を卓上に置くことを前提とすること。
- 従来研究として、研究室のロボットカフェ（注文ロボットがテーブルを割り当て、配膳ロボットがテーブルで商品名を読み上げて
  客に確認する）を引用し、客に席を選ばせる場合に番号札が要る、という流れで本研究につなぐ。
- **アレルギー・医療・給食を背景に使わない**（本人の判断）。
- 番号札・卓上端末・声で尋ねる方式などの対抗手段は、**論破しようとしない**。
  事実（番号札の配布と回収が人手になる 等）を述べ、比較実験の条件に入れる。
- 研究室の実験用のカフェ（名称は `CLAUDE.local.md`）を舞台にする。ファミリーレストランは対象外。
- 注文ロボットと配膳ロボットは別の機体であり、客の外見をロボット間で引き継ぐ。
- 範囲の前提は文で明記する：客は注文位置に1人ずつ立ち、各自が自分の商品を注文する。
  代表者のまとめ注文、話者の特定、置き場所の探索、プライバシーは扱わない。
- 比較する人物再識別手法は OSNet（卒業研究のベースライン）・CLIP-ReID・KPR。
  卒業研究の結果（3名の候補で、背面から観測した条件で正しく選べたのは 6 試行中 1 回）を課題の根拠に使う。

### 14.2 自己添削の問い

初めて読む人（同じ分野だが、この研究を知らない人）になったつもりで、1文ずつ次を問う。
答えが本文に書かれていなければ直す。指摘は `要旨添削例.md` §4 の形式（種類の記号・箇所・ダメな点・直した文）で書く。

1. この研究の課題は何か。1文で言えるか。はじめにの終わりまでに書かれているか
2. 表題の語（比較・評価・設計）は、本文のどこで回収されているか
3. 研究の目的と、各実験の目的は対応しているか。評価が目的になっていないか
4. 各名詞について「何の？」「何に対する？」と聞かれたら、答えは本文にあるか
5. 初めて出る語・略語・記号に定義があるか。同じものを別の語で呼んでいないか
6. 手法・モデル・センサ・閾値・条件・評価尺度・比較手法に「なぜそれか」と聞かれたら、答えは本文にあるか
7. 数量の語（複数、一定、十分、大幅、ほぼ）が数値になっているか
8. 実験を第三者が再現できるか（環境の図、回数、機器の型番、判定の基準、評価尺度の式）
9. 図は本文で引用され、本文と図の用語・段階の数が一致しているか。図の説明だけで大筋が追えるか
10. 同じことを2回以上書いていないか。削っても意味が変わらない文はないか
11. 主語のない文、「の」や「を」が続く文、読点で3つ以上つないだ文はないか
12. 確かめていない範囲まで言い切っていないか。逆に、確かめた課題や結果を「可能性がある」で弱めていないか
13. はじめにで出していない課題・用語が、後の章で初めて出ていないか
14. 名前を出した道具・データセット・ロボットに引用があるか。本文で使わない文献が載っていないか

| 聞かれたこと | 要旨で先に書くこと |
|---|---|
| 対象の形・環境・条件が違っても使えるか | 考察・限界の節に、確かめた範囲と、使えない条件を書く |
| その評価項目は一般的なものか | 評価尺度の出典か、選んだ理由を書く |
| 実際の現場で試したか。理想の環境と条件が違わないか | 実験環境と実際の現場との違いを、限界として書く |
| （結論に対して）それはまとめである。考察はあるか | 結果の理由と根拠を、考察として分けて書く |
| 表や図の「3：2」は何と何か | 比・記号・略語をすべて定義する |
| なぜそうなるのか | 結果の理由を書く（§14.1 K8） |
| 使い物になる基準（どこまでできれば良いか）はどこか | 実験目的の節に、目標とする値を書く |
| 改善案は。次に何をどう検証するか | おわりにの今後の課題を、今回わかった限界に対応させる |
| 未知の対象や、背景と色が似ている場合はどうなるか | 失敗した条件と、その数を結果に書く |

### 14.5 過去の要旨から分かること

2020〜2025 年度の卒業論文と修士論文の要旨 17 本（所属研究室と近い分野の研究室）を読み、構成と文体を数えた。

- **章立て**：ほぼ全てが、はじめに／手法（中身を表す題）／〇〇実験（何の実験かを表す題）／まとめ・おわりに の4章。
  関連研究を、はじめにの中で書くものが多い。ただし `guide.tex` は関連研究を2章に独立させているので、`guide.tex` に従う。
- **参考文献**：3〜8 件。
- **1文の平均の長さ**：57〜143 字（中央値 76 字）。17 本のうち 11 本が、今の基準（句点まで 70 字以内）を超える。長さは真似しない。
- **文体**：「など」「この」「〜と考えられる」「提案」を使う要旨が多い。今の添削では指摘されるので真似しない。
- **良い書き方**：関連研究と会話する書き方、課題の場面と原因を段を踏んで書く書き方、結果を絶対値で比べる書き方は真似する（`要旨添削例.md` §3）。

## 15. 一般的な技術文書の書き方（出典）

研究室の指南（`guide.tex`）と添削に加えて、次の一般的な指針に沿う。§4〜§8 の決まりの多くは、これらの指針と同じことを述べている。

- **パラグラフ・ライティング**：1つの段落に1つの主張を置き、段落の先頭文で主張を述べる。
  大阪大学附属図書館「パラグラフ・ライティング講座」（https://www.library.osaka-u.ac.jp/doc/LS_20240207_paragraphwriting.pdf）、
  永井敦「パラグラフ・ライティングの基本ルール」神戸大学（https://da.lib.kobe-u.ac.jp/da/kernel/0100482093/0100482093.pdf）
- **理科系の作文技術**：事実と意見を分けて書き、明確に言い切り、1つの文には1つのことだけを書く。
  木下是雄『理科系の作文技術』中公新書、1981
- **extended abstract の構成**：問題、先行研究で足りない点、手法の要点、主要な結果、限界の順に書き、
  図表は筋に欠かせないものだけを置く。
  https://aeturrell.github.io/coding-for-economists/craft-extended-abstracts.html
